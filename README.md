# Aurora Visuals — визуальный клиент для Minecraft 1.21.11 (Fabric)

[![build](https://github.com/amir2013shai-byte/aurora-visuals/actions/workflows/build.yml/badge.svg)](https://github.com/amir2013shai-byte/aurora-visuals/actions/workflows/build.yml)
[![release](https://img.shields.io/github/v/release/amir2013shai-byte/aurora-visuals?label=download)](https://github.com/amir2013shai-byte/aurora-visuals/releases/latest)

Открытая реализация идей визуального клиента **Never Visuals** ([nevervisuals.su](https://nevervisuals.su/)):
ESP-подсветка цели, следы, частицы, кейпы, кастомный туман, Dynamic Island, собственное меню
и оптимизация. Всё написано с нуля, без проверок лицензии, без привязки к аккаунту и без
взаимодействия с сервером — это чисто клиентский визуальный мод.

* Версия игры: **Minecraft 1.21.11**
* Загрузчик: **Fabric Loader 0.20.1+**, **Fabric API 0.141.6+1.21.11**
* Java: **21+**
* Сторона: **только клиент** (`environment: client`)

Готовый файл: **[aurora-1.7.0.jar](https://github.com/amir2013shai-byte/aurora-visuals/releases/download/v1.3.0/aurora-1.7.0.jar)** (сборка `build/libs/aurora-1.7.0.jar`).

---

## Установка

1. Установите Fabric Loader 0.20.1+ для Minecraft 1.21.11.
2. Положите в папку `mods`:
   * `aurora-1.7.0.jar`
   * `fabric-api-0.141.6+1.21.11.jar`
3. Запустите игру. В логе будет строка: `Aurora Visuals v1.7.0 инициализирован — 69 модулей`.
4. Нажмите **Right Shift** — откроется меню клиента.

Конфиг создаётся автоматически: `.minecraft/config/aurora/config.json`.

---

## Меню (Right Shift)

* Слева — категории: **Render / Particles / Interface / Player / Misc**.
* В центре — модули категории (или результаты поиска) с переключателем.
* Справа — настройки выбранного модуля: тумблеры, ползунки, режимы, цвет (hue-полоса), строки, бинд.
* В шапке — поиск по всем модулям, кнопка темы (NOVA / AURORA / MIDNIGHT / SUNSET / MATRIX) и закрытие.
* Настройки и состояние модулей сохраняются автоматически (при закрытии меню, при выходе и раз в 15 секунд при изменениях).

### Что нового в 1.7.0

**BetterDebug** — замена ванильного F3. Вместо простыни текста две аккуратные панели:

* **слева**: FPS, пинг, TPS (по тикам клиента), занятая/выделенная память, число сущностей, число модулей;
* **справа**: XYZ с точностью до 0.1, координаты блока и чанка, сторона света и скорость в бл/с,
  измерение и биом, время мира и номер дня, блок под прицелом с его стороной и дистанцией.

Работает в двух режимах: «только по F3» (наш оверлей появляется вместо ванильного — сам F3
по-прежнему переключается ванильной клавишей) и «всегда». Ванильный оверлей гасится миксином
в `DebugScreenOverlay#render` (`method_1846` в jar), при этом `showDebugScreen()` продолжает
читать `debugEntries.isOverlayVisible()`, поэтому факт нажатия F3 мы видим корректно.

### Что нового в 1.6.0

**Чистая картинка 2** (4 миксина + 1): `NoHurtCam` (`GameRenderer#bobHurt`),
`NoFireOverlay` (`ScreenEffectRenderer#renderFire`), `AntiBlind` (`LivingEntity#getEffectBlendFactor`),
`NoTotemAnim` (`GameRenderer#displayItemActivation`), `ItemPhysics` (`ItemEntityRenderer#submit`).

**Мир-визуал**: `BlockOverlay` (обводка блока под прицелом по `VoxelShape`), `BreakProgress`
(читает приватные `destroyBlockPos`/`destroyProgress` через `@Accessor`-миксин), `Trajectory`
(симуляция полёта с `ClipContext`), `ItemESP` (подписи и цвет по редкости).

**Чат-твиты**: `AntiClear` (`ChatComponent#clearMessages`), `ChatMention` (звук при упоминании,
`ChatComponent#addMessage`), `ChatSuffix` (`@ModifyVariable` в `ClientPacketListener#sendChat`),
плюс команда `.copy [строк]` — копирует последние сообщения в буфер обмена.

**Minimap** — настоящая карта блоков: цвет из `MapColor` верхнего блока, картинка собирается
в `NativeImage` и грузится в `DynamicTexture`, обновление раз в 0.5 с, маркеры игроков и вейпоинтов.

_Оговорки: `ItemPhysics` крутит только модель на земле (коллизии и физику не трогает);
`Minimap` север-вверх и без кеша чанков — обновляется пересборкой картинки._

### Что нового в 1.5.0

**Чат-клиент с командами** — свои команды с префиксом «.», обрабатываются локально и на сервер не уходят
(перехват в `ClientPacketListener#sendChat` через `ChatMixin`):

| Команда | Что делает |
|---|---|
| `.help` | список всех команд |
| `.toggle <модуль>` / `.t <модуль>` | включить/выключить модуль |
| `.bind <модуль> <клавиша>` / `.unbind <модуль>` | назначить или снять бинд |
| `.friend add\|remove\|list [ник]` | управление списком друзей |
| `.wp add\|remove\|list [имя]` | точки Waypoints (добавление — по текущей позиции) |
| `.cfg save\|load\|list [имя]` | профили настроек |
| `.theme <тема>` / `.modules` / `.hud reset` | тема меню, список включённого, сброс смещений HUD |
| `.cosmetic <модель>` / `.version` | надеть шляпу, версия клиента |
| `.copy [строк]` | скопировать последние сообщения чата в буфер |

**Профили конфигов** — `config/aurora/profiles/<имя>.json`, переключение через `.cfg save pvp` / `.cfg load pvp`.

**Новые модули (7)**: `StorageESP`, `BlockESP` (подсветка через стены по блок-сущностям и секциям чанков),
`Radar`, `ServerInfo`, `StaffList`, `Clock`, `FpsGraph`. Итого 55 модулей.

_Скан через `LevelChunkSection#maybeHas` — секции без нужных блоков отсекаются до перебора,
поэтому BlockESP не жрёт CPU даже с радиусом 8 чанков._

### Что нового в 1.4.0

Паритет с включённым списком Never Visuals со скрина (19 функций, из них 5 у нас уже было):

* **13 новых модулей**: `Footprints`, `Waypoints`, `Seasons`, `BlockShadows`, `DynamicLights`,
  `BlockPlace`, `CrystalColor`, `Animations`, `MainMenuSetting`, `Friends`, `NoPause`, `ItemScroller`, `Zoom`.
* **Редактор HUD** — кнопка `HUD` в заголовке меню: тянем строку мышью, элемент HUD смещается;
  смещения живут в `config/aurora/hud_offsets.json`, ПКМ по строке — сброс, СКМ — вкл/выкл модуль.
* **TargetHUD получил аватар** — настоящая голова игрока через `PlayerFaceRenderer`.
* **5 новых миксинов** (всего 11): `Minecraft#isPaused` (NoPause), `AbstractContainerScreen#mouseScrolled`
  (ItemScroller), `EndCrystalRenderer#submit` (CrystalColor), `ItemInHandRenderer#renderHandsWithItems`
  (Animations), `TitleScreen#renderBackground` (MainMenuSetting).

_Честные ограничения 1.4.0: `DynamicLights` — визуальное гало, а не настоящий свет (для него нужна правка
LightEngine); `Animations` крутит только позу предмета в руке, а не скорость взмаха; `MainMenuSetting`
меняет подложку главного меню, кнопки остаются ванильные._

### Что нового в 1.3.0

* **Экран «Косметика»** — кнопка `КОСМЕТИКА` в заголовке меню: сетка из 12 шляп с превью,
  ЛКМ надевает модель (Hats включается автоматически), ПКМ снимает, выбор сохраняется в конфиг.
* **Hats** — моделей стало 12: добавлены венок, бандана, наушники, рюкзак, треуголка и маска.

  включаются через приватный `GameRenderer#setPostEffect` (доступ — `@Invoker` в `GameRendererAccessor`):
  публичного сеттера пост-эффекта в 1.21.11 нет.
* **HitColor** — миксин в `LivingEntityRenderer#getModelTint`: когда у сущности `hasRedOverlay`
  (вспышка урона), тинт модели подменяется на выбранный цвет; дополнительно можно включить рамку.
* **NameTags** — ники в мире рисуются через `SubmitNodeStorage#submitText` с билборд-разворотом
  по кватерниону камеры, ниже — полоса здоровья квадами.

_Ограничение MotionBlur: цепочка статична, uniform'ы `Radius` не зависят от скорости камеры —
это «постоянный» смаз, а не полноценный camera-based motion blur._

### Что нового в 1.2.0

* **Keystrokes** — WASD/пробел/мышь на экране, счётчик CPS.
* **PotionHUD** — эффекты с таймером, уровнем и цветом зелья.
* **ArmorHUD** — броня и предмет в руке с полосками прочности.
* **PlayerList** — игроки на сервере: пинг, дистанция, сортировка.
* **CoordsHUD** — координаты, биом, измерение, сторона света (+ пересчёт в координаты Нижнего мира).

_Порт под 1.21.11 потребовал правок: `GameProfile` стал record (`name()`/`id()` вместо `getName()`/`getId()`), броня теперь только через `getItemBySlot(EquipmentSlot)`, а `ResourceKey.location()` переименован в `identifier()`._

### Что нового в 1.1.0

* **Tracers** — линии от прицела к целям с градиентом по дистанции.
* **SkeletonESP** — скелет игрока внутри модели, окраска по здоровью.

* **Crosshair** — свой прицел (крест, круг, точка, ромб).
* **HitSounds** — клиентский звук попадания.
* **Trails** получил режимы «Лента» и «Призраки».

## Как это устроено

```
src/client/java/su/aurora/
├── Aurora.java                 константы мода, Identifier-хелпер
├── AuroraClient.java           точка входа: модули, конфиг, бинды, события тика/рендера/HUD
├── core/
│   ├── Category.java           категории
│   ├── Module.java             базовый модуль: вкл/выкл, бинд, настройки, хуки
│   ├── ModuleManager.java      реестр модулей
│   ├── ConfigManager.java      JSON-конфиг (Gson)
│   └── Notifications.java      очередь уведомлений для Dynamic Island
├── setting/                    Setting / Boolean / Number / Mode / Color / String
├── util/
│   ├── Render3D.java           рисование в мире (линии, заливка, круги, ромбы, пирамиды)
│   ├── Render2D.java           GUI-примитивы: скругления, градиенты, текст, scissor
│   ├── ColorUtil.java          ARGB, радуга, пульсация, лерп
│   ├── PlayerUtil.java         цель под прицелом, ближайший игрок, HP, пинг, FPS
│   └── TimerUtil.java          таймеры, partial tick, позиция камеры
├── ui/
│   ├── ClickGuiScreen.java     меню клиента (категории, поиск, настройки, темы)
│   └── HudRenderer.java        диспетчер HUD-модулей
├── modules/{render,particles,hud,misc,player}/...
└── mixin/                      FogRenderer, WeatherEffectRenderer, ParticleEngine, EntityRenderDispatcher
```

Ключевая особенность 1.21.11: мир больше не рисуется напрямую через `MultiBufferSource`.
Каждый модуль собирает геометрию и отправляет её одним
`OrderedSubmitNodeCollector#submitCustomGeometry(PoseStack, RenderType, (pose, consumer) -> …)`
из `WorldRenderEvents.BEFORE_DEBUG_RENDER`. Поэтому `Render3D` даёт два буфера:
`lines(...)` (RenderTypes.LINES / LINES_TRANSLUCENT, формат POSITION_COLOR_NORMAL) и
`quads(...)` (RenderTypes.debugQuads, двусторонняя заливка).

HUD рисуется через `HudElementRegistry.addLast(...)`, бинд меню — `KeyMapping.Category.register(...)`,
что корректно показывается в стандартных настройках управления.

### Добавить свой модуль

```java
public class MyModule extends Module {
    private final BooleanSetting glow = addBoolean("Свечение", true);
    private final ColorSetting color = addColor("Цвет", 0xFF7C5CFF);

    public MyModule() {
        super("MyModule", "Описание для меню", Category.RENDER);
    }

    @Override
    public void onWorldRender(WorldRenderContext context) {
        Render3D.lines(b -> b.circle(myPlayerPosition(), 1.2, color.get(), 2.5f, 64));
    }

    @Override
    public void onTick() { /* раз в тик, только когда модуль включён */ }
}
```

и зарегистрировать в `ModuleManager.init()`: `register(new MyModule());`.

## Ограничения и честные оговорки

* Мод **скомпилирован и проходит запуск клиента** (в тестовом окружении в логе видно успешную
  инициализацию всех 22 модулей и применение миксинов). Полноценно протестировать мировую
  геометрию не удалось: в среде сборки нет GPU и всего 2 ГБ ОЗУ, клиент запускался через
  программный OpenGL и был вынужден закрыться на загрузке атласов.
* Весь мировой рендер обёрнут в `try/catch` по каждому модулю: если конкретный эффект
  где-то не сработает, в лог уйдёт ошибка модуля, а игра продолжит работать.
* `Optimization` использует raycast от камеры к bounding box сущности — это дешево, но не
  бесплатно; на слабых системах лимит дистанции стоит уменьшать.
* В отличие от оригинала здесь нет: аккаунтов, ключей, HWID-привязки, клиентского чата,
  магазина косметики и ~140 модулей. Реализованы именно визуальные идеи с сайта.
* Мод не содержит боевых/автоматических функций (killaura, aimbot и т.п.) — только визуал,
  интерфейс и оптимизация.
